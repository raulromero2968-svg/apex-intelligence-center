# Neo4j Setup Guide for Micro-Genesis

This guide walks you through setting up Neo4j for the Micro-Genesis TCG Market Intelligence System.

## Option 1: Neo4j AuraDB Free Tier (Recommended)

AuraDB provides a free cloud-hosted Neo4j instance, perfect for development and small-scale production.

### Step 1: Create an AuraDB Instance

1. Go to [console.neo4j.io](https://console.neo4j.io)
2. Sign up or log in with your account
3. Click "Create Database"
4. Select "AuraDB Free" tier
5. Choose a region close to you
6. Note your credentials:
   - **Connection URI**: `neo4j+s://xxxxxxxx.databases.neo4j.io`
   - **Username**: `neo4j` (default)
   - **Password**: Generated password (save this!)

### Step 2: Configure Environment Variables

```bash
# Add to your .bashrc, .zshrc, or .env file
export NEO4J_URI='neo4j+s://xxxxxxxx.databases.neo4j.io'
export NEO4J_USER='neo4j'
export NEO4J_PASSWORD='your-generated-password'
```

### Step 3: Run Setup Script

```bash
cd micro_genesis
python3 setup_neo4j.py
```

Expected output:

## Option 2: Local Neo4j Docker

For local development without cloud dependencies.

### Step 1: Start Neo4j Container

```bash
docker run \
    --name micro-genesis-neo4j \
    -p 7474:7474 -p 7687:7687 \
    -e NEO4J_AUTH=neo4j/password123 \
    -e NEO4J_PLUGINS='["apoc"]' \
    -d neo4j:5.15.0
```

### Step 2: Configure Environment

```bash
export NEO4J_URI='bolt://localhost:7687'
export NEO4J_USER='neo4j'
export NEO4J_PASSWORD='password123'
```

### Step 3: Access Neo4j Browser

Open [http://localhost:7474](http://localhost:7474) to access the Neo4j Browser UI.

## Schema Overview

The Micro-Genesis schema includes the following node types:

### Core Nodes

| Node Label | Description |
|------------|-------------|
| `Hypothesis` | Market hypotheses generated by Claude |
| `DataCollectionTask` | Tasks for data collection agents |
| `DiscoveryCycle` | Discovery cycle tracking |
| `Insight` | AI-generated market insights |

### Data Nodes

| Node Label | Description |
|------------|-------------|
| `Card` | TCG card information |
| `Set` | TCG set information |
| `Price` | Price data points |
| `Tournament` | Tournament events |
| `Deck` | Tournament deck data |
| `DataSource` | Data source metadata |
| `MarketEvent` | Market-affecting events |

### Key Relationships

```cypher
// Hypothesis relationships
(h:Hypothesis)-[:GENERATED_IN]->(c:DiscoveryCycle)
(h:Hypothesis)-[:REQUIRES_DATA]->(t:DataCollectionTask)
(h:Hypothesis)-[:VALIDATED_BY]->(i:Insight)

// Card relationships
(c:Card)-[:BELONGS_TO]->(s:Set)
(c:Card)-[:HAS_PRICE]->(p:Price)
(c:Card)-[:PLAYED_IN]->(d:Deck)

// Task relationships
(t:DataCollectionTask)-[:TARGETS]->(s:DataSource)
(t:DataCollectionTask)-[:PRODUCED]->(p:Price)
```

## Useful Cypher Queries

### View All Hypotheses

```cypher
MATCH (h:Hypothesis)
RETURN h.text, h.confidence, h.status, h.category
ORDER BY h.confidence DESC
```

### View Pending Tasks

```cypher
MATCH (t:DataCollectionTask {status: 'Pending'})
RETURN t.id, t.type, t.target_url, t.priority
ORDER BY t.priority DESC
```

### View Discovery Cycle History

```cypher
MATCH (c:DiscoveryCycle)
RETURN c.cycle_number, c.status, c.hypotheses_generated, c.tasks_completed
ORDER BY c.cycle_number DESC
```

### View Price History for a Card

```cypher
MATCH (c:Card {name: 'Charizard'})-[:HAS_PRICE]->(p:Price)
RETURN p.timestamp, p.price_usd, p.condition, p.grade
ORDER BY p.timestamp DESC
LIMIT 20
```

### View Hypothesis Validation Rate

```cypher
MATCH (h:Hypothesis)
WITH h.status as status, count(*) as count
RETURN status, count,
       toFloat(count) * 100.0 / sum(count) as percentage
```

### View Knowledge Graph Statistics

```cypher
CALL apoc.meta.stats() YIELD labels
RETURN labels
```

```cypher
// Export all hypotheses
CALL apoc.export.cypher.query(
    "MATCH (h:Hypothesis) RETURN h",
    "hypotheses_backup.cypher",

```

## Performance Optimization

### Index Usage

The setup script creates indexes on frequently queried properties:
- `Hypothesis.status`
- `Hypothesis.confidence`
- `DataCollectionTask.status`
- `DataCollectionTask.priority`
- `Card.name`, `Card.game`
- `Price.timestamp`

### Query Optimization Tips

1. **Use parameters** instead of string concatenation
2. **Limit results** with `LIMIT` clause
3. **Use indexes** by querying on indexed properties first
4. **Avoid Cartesian products** with proper `MATCH` patterns

### Memory Configuration (Self-hosted)

For local installations, adjust memory in `neo4j.conf`:

```properties
# Heap memory
dbms.memory.heap.initial_size=512m
dbms.memory.heap.max_size=1G

# Page cache
dbms.memory.pagecache.size=512m
```

## Troubleshooting

### Connection Refused

```
Error: Could not connect to Neo4j at bolt://localhost:7687
```

**Solutions:**
1. Check if Neo4j is running
2. Verify the port is correct
3. Check firewall settings

### Authentication Failed

```
Error: Authentication failed for user 'neo4j'
```

**Solutions:**
1. Verify password is correct
2. Reset password in Neo4j Browser
3. Check if user exists

### Constraint Already Exists

```
Error: Constraint already exists
```

This is expected on subsequent runs. The setup script uses `IF NOT EXISTS` clauses.

### Out of Memory

```
Error: Java heap space
```

**Solutions:**
1. Increase heap memory in `neo4j.conf`
2. Use AuraDB for automatic scaling
3. Optimize queries to use less memory
