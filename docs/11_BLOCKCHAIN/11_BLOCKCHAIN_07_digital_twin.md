# Digital Twin System

## Overview

Digital Twins are blockchain-based NFTs that represent physical trading cards. Each digital twin is cryptographically linked to a physical card via a unique fingerprint hash, creating an immutable bridge between the physical and digital worlds.

## Digital Twin Lifecycle

### 1. Creation (Minting)

**Trigger**: Physical card scanned and fingerprinted via VARC Scan v1

**Process**:
1. Generate unique fingerprint (256-d vector + 64-char hex)
2. Verify fingerprint uniqueness (no existing digital twin)
3. Mint ERC-721 NFT on blockchain
4. Store fingerprint hash in NFT metadata
5. Create on-chain verification record

**Metadata Structure**:
```json
{
  "fingerprintHash": "a1b2c3d4...",
  "hashVersion": "v1",
  "cardId": "pokemon_base_set_charizard",
  "grade": 9.5,
  "imageUrl": "https://...",
  "createdAt": "2025-11-20T10:00:00Z"
}
```

### 2. Ownership

**Physical Card Ownership**:
- Tracked via user accounts in Apex Intelligence
- Linked to digital twin via fingerprint hash

**Digital Twin Ownership**:
- Tracked on blockchain (ERC-721 standard)
- Wallet address owns the NFT
- Immutable ownership history

**Synchronization**:
- Physical card transfer → Digital twin transfer (manual or automated)
- Both ownership records must match for verification

### 3. Verification

**Proof-of-Existence**:
1. Scan physical card → Generate fingerprint
2. Query blockchain for NFT with matching fingerprint hash
3. Verify NFT exists and metadata matches
4. Confirm ownership (wallet address matches user)

**Anti-Fraud Measures**:
- Fingerprint uniqueness prevents duplicate digital twins
- On-chain verification prevents tampering
- Hash versioning allows algorithm updates

### 4. Transfer

**Physical Card Transfer**:
1. Seller initiates transfer
2. Buyer receives physical card
3. Digital twin NFT transferred to buyer's wallet
4. Ownership records updated on-chain

**Digital Twin Transfer**:
- Standard ERC-721 transfer
- Immutable on-chain record
- Links to physical card via fingerprint hash

## Fingerprint Requirements for Digital Twins

### Uniqueness

- **Target**: 99.9% collision-free within same card/grade cohort
- **Method**: High-entropy 256-d vector + SHA-256 hex digest
- **Deduplication**: pgvector nearest-neighbor search before minting

### Versioning

- **Hash Version**: Tracks fingerprint algorithm version (e.g., "v1")
- **Migration**: Future versions can coexist with v1
- **Compatibility**: Digital twins reference hash version in metadata

### Storage

- **Vector**: Stored in PostgreSQL with pgvector (for similarity search)
- **Hex Digest**: Stored in NFT metadata (on-chain or IPFS)
- **Linkage**: Database links fingerprint → NFT token ID

## Integration with VARC Scan v1

### Scan → Digital Twin Flow

1. **Scan**: User scans card with mobile camera
2. **Fingerprint**: VARC generates fingerprint (vector + hex)
3. **Deduplication**: Check for existing fingerprints
4. **Decision**:
   - If duplicate: Link to existing digital twin
   - If unique: Offer to create new digital twin
5. **Minting**: Create NFT on blockchain (if user opts in)
6. **Linking**: Store fingerprint → NFT mapping in database

### Digital Twin Metadata

Fingerprints generated by VARC Scan v1 include:
- `fingerprintVector`: 256-d normalized vector
- `fingerprintHex`: 64-char SHA-256 hex digest
- `hashVersion`: Algorithm version (e.g., "v1")
- `grade`: Card grade (if available)
- `cardId`: Card identifier

All of these are suitable for inclusion in digital twin NFT metadata.

- **Primary Network**: Recommended for most digital twins
- **Gas Costs**: Lower than Ethereum mainnet
- **Speed**: Fast transaction confirmation
- **Standards**: ERC-721 compatible

### Ronin

- **Gaming Focus**: Optimized for gaming NFTs
- **Use Case**: Gaming-focused trading cards
- **Standards**: ERC-721 compatible

## Future Enhancements

### Automated Sync

- Physical card ownership changes → Automatic digital twin transfer
- Requires wallet integration and user consent

### Multi-Signature Verification

- High-value cards: Require multiple signatures for transfer
- Enhanced security for premium digital twins

### Cross-Chain Bridges

- Transfer digital twins between networks
- Maintain fingerprint linkage across chains

### Marketplace Integration

- Trade digital twins on NFT marketplaces
- Physical card ownership verified via fingerprint

## Security & Privacy

### Fingerprint Privacy

- Fingerprints are deterministic (same card = same fingerprint)
- No personally identifiable information in fingerprints
- Hash versioning allows algorithm updates

### Ownership Privacy

- Blockchain ownership is public (by design)
- Physical card ownership can be private (user accounts)
- Users control linkage between physical and digital ownership

### Fraud Prevention

- Fingerprint uniqueness prevents duplicate digital twins
- On-chain verification prevents tampering
- Immutable ownership history on blockchain
